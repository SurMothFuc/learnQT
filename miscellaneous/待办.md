## P0 正确性优先修复

- [ ] 完善 ray epsilon 策略。表面新光线和阴影路径已有沿方向的固定 `0.0005` 偏移；仍需验证尺度适应、几何法线偏移、掠射角、薄片、透明穿透和体积散射，避免把固定阈值当成通用解。
- [ ] 修正 OIDN normal 辅助输入范围。`shaders/pathtrace.frag` 将 normal 写成 `[0, 1]` 编码，`src/renderer.cpp` 读回后直接交给 OIDN；应在交给 OIDN 前恢复到 `[-1, 1]` 的世界空间或视空间法线。
- [ ] 重新检查透明材质与体积路径的首个可见 hit 记录逻辑，确保折射、透明穿透、体积散射路径输出给 OIDN 的 normal/albedo 稳定且语义一致。
- [ ] 修正 HDR MIS 的 PDF 查询一致性。当前 `hdrCache` 同时承担采样 LUT 和方向 PDF 贴图职责，`SampleHdr()` 通过 `RG` 重映射随机数到被采样 texel，但 `hdrPdf(direction)` 又按方向 UV 读取 `B` 通道，可能拿到的是 cache 单元本身的概率而不是该方向的真实概率；应拆分 direction-to-pdf 贴图，或让 `SampleHdr()` 返回采样 texel 及其 pdf，并保证 NEE 与 BSDF-side `LightPdf()` 使用同一测度。

## P1 采样与光照质量

- [ ] 补全 HDR 环境贴图参数化。MIS 路径已有初步接入，但仍缺环境强度、旋转、背景显示、透明背景和 uniform light fallback 等参考项目已有的环境光选项。
- [ ] 完善 emissive triangle 的双面发光约定。项目目标是三角形光源双面发光，因此 NEE 采样、BSDF 命中发光、shadow ray 可见性和面积到立体角 PDF 都要使用一致的双面测度；不能一处按双面贡献、一处按单面 PDF 或单面可见性处理。
- [ ] 补齐解析光源的定量验证。sphere / sun 已有场景配置与代码契约测试；仍需专门对比有限光源 PDF、可见性、NEE/MIS 权重和能量，而不是只依赖预设截图非黑检查。
- [ ] 细化发光贴图功率估计。当前按整张纹理平均值给每个三角形加权，可能给实际 UV 区域不发光的面分配过多概率；需按 UV 覆盖区域估计功率，并评估纹理域重要性采样。
- [ ] 将 NEE、BSDF 采样和 power heuristic 合并成同一套直接光照路径，统一处理 hit emissive、环境光命中、解析光源命中和显式光源采样的权重，避免重复计光或漏权重。
- [ ] 明确 delta/specular 与 rough transmission 的光源采样规则。理想 delta 反射/折射继续沿唯一 BSDF 方向追踪，应跳过直接光采样，并在下一个环境或发光命中处按 delta 链规则累计；rough reflection / rough transmission 才参与直接光照采样，并与 light pdf 做 MIS。
- [ ] 为体积散射补齐直接光照与 Volume MIS。介质内部采样到散射点后，也应采样环境光和解析光源；shadow ray 不能只做二值遮挡，需要按参考实现思路评估透明/体积路径上的 transmittance。
- [ ] 改进 Sobol 序列扰动。当前 shader 里仍使用 Cranley-Patterson rotation，后续应改成每像素数字扰动、Owen scrambling 或数字异或，并保持维度和 bounce 的可复现映射。
- [ ] 增加 roughness mollification 作为可选降 firefly 策略。只在完成同 spp 噪声、能量和高光形状对比后启用，避免把粗糙度钳制当作默认正确性修复。

## P3 性能与架构

- [ ] 先增加 GPU timer query 和关键阶段计时，再决定是否改 compute shader。至少分别测 pathtrace pass、history save、denoise readback、OIDN execute、screen composite。
- [ ] 给 BVH 遍历增加 profile 指标：`nodeVisits`、`leafVisits`、`triTests`、`maxStackDepth`，先定位是遍历层级、三角形测试还是纹理缓冲访存瓶颈。
- [ ] 优化 OIDN 读回路径。`Renderer::performDenoising()` 使用 PBO 后立即 `glMapBuffer()`，后面还有 `glFinish()`，实际仍可能同步阻塞；应改成延迟一帧 map、fence sync 或只在最终帧读回。
- [ ] 将场景拆分为 TLAS/BLAS，支持实例化和动态更新。mesh 几何、材质表、实例 transform、灯光和环境贴图应分离上传；相机、材质或单个实例 transform 变化时不应重复重建整棵 BVH。
- [ ] 后续按需增加对象树、对象变换和局部材质编辑器。首版场景管理已完成，当前实例矩阵可持久化，但运行时仍展开三角形，材质 UI 仍统一覆盖常量。
- [ ] 优化首次启动体验。运行时切换/重载/导入已后台化，首次窗口构造仍同步加载默认场景；需评估启动页、取消加载和更细粒度进度。
- [ ] 优化三角形和 BVH 数据布局。完成 profile 后再评估 AoS/SoA、节点压缩、三角形属性拆分、纹理缓冲访问顺序等方案。
- [ ] 将降噪部分进一步模块化，明确实时预览降噪、最终帧降噪、辅助 buffer 生成和 OIDN filter 生命周期的边界。
- [ ] 保留 preview / final 两种渲染路径：预览模式优先交互响应和低同步成本，最终模式优先累计质量、NEE/MIS 质量和降噪质量。
- [ ] 继续补齐渲染选项：`RRDepth`、独立渲染分辨率、denoiser frame cadence、ACES/tonemap toggle、hide emitters、transparent background。已有 `maxBounces` 与 `maxRenderFrames`（完整累计轮次限制，0 为无限），不再把累计上限列为未实现；还需明确同 spp 验收计数。新增选项应进入 `RenderParams::Snapshot` 或场景配置。
- [ ] 建立 shader feature define 管理。按 `lights/env/alpha/medium/volume MIS/normal map/tonemap` 等功能组合生成 shader，而不是把所有路径硬塞进单一路径；每个 define 要有默认值、触发条件和回归场景。
- [ ] 评估 Sobol 预计算收益。先确认当前随机数生成在 CPU 上传 uniform 还是 shader 使用上是否真是瓶颈，再决定是否预计算或改为纹理/SSBO。

## 验证要求

- 代码项实现后，先跑 `cmake --build build --config Release` 和 `ctest --test-dir build -C Release --output-on-failure`，保留现有 8 项测试。
- 已有卧室/路灯截图与像素检查是回归基线，不等于采样算法验证；后续补充 Veach 多光源、玻璃折射、环境贴图、体积介质四类定量对比场景。
- `--regression-frames` 统计展示事件，不等于严格固定 spp；同 spp 比较应使用明确的完整累计/采样计数。
- 采样类改动必须对比同样 spp 下的噪声、能量守恒和 firefly 情况，不能只看单张图是否变亮。
- 性能类改动必须先提交 profile 数据，再改数据布局或 shader 架构；避免在未定位瓶颈前直接重写渲染路径。
